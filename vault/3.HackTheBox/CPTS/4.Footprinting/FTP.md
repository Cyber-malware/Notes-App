The `File Transfer Protocol` (`FTP`) is one of the oldest protocols on the Internet. The FTP runs within the application layer of the TCP/IP protocol stack. Thus, it is on the same layer as `HTTP` or `POP`.
Here ftp  [commands](https://web.archive.org/web/20230326204635/https://www.smartfile.com/blog/the-ultimate-ftp-commands-list/) and here [status_codes](https://en.wikipedia.org/wiki/List_of_FTP_server_return_codes).

**FTP (File Transfer Protocol) uses two ports:**

1. **Control Channel (Port 21)**
    
    - **Purpose:** Used for sending commands (e.g., upload, download, list files) and receiving responses from the server.
    - **How it works:** Client sends instructions; server sends status codes (success, failure).
    - **Always open** during the session.
        
2. **Data Channel (Port 20)**
    
    - **Purpose:** Used for transferring the actual files between client and server.
    - **How it works:** Once commands are sent via Port 21, the data is transferred over Port 20.
    - **Only open during file transfer

**TFTP:**

`Trivial File Transfer Protocol` (`TFTP`) is simpler than FTP and performs file transfers between client and server processes. However, it `does not` provide user authentication and other valuable features supported by FTP. In addition, while FTP uses TCP, TFTP uses `UDP`, making it an unreliable protocol and causing it to use UDP-assisted application layer recovery.

|**Commands**|**Description**|
|---|---|
|`connect`|Sets the remote host, and optionally the port, for file transfers.|
|`get`|Transfers a file or set of files from the remote host to the local host.|
|`put`|Transfers a file or set of files from the local host onto the remote host.|
|`quit`|Exits tftp.|
|`status`|Shows the current status of tftp, including the current transfer mode (ascii or binary), connection status, time-out value, and so on.|
|`verbose`|Turns verbose mode, which displays additional information during file transfer, on or off.|
**VsFTPd:**

## Foot-printing the Service

we can use various scanner to get information of ftp but mostly we use nmap. Because nmap comes with  [Nmap Scripting Engine](https://nmap.org/book/nse.html) (`NSE`).

```shell-session
sudo nmap --script-updatedb

Starting Nmap 7.80 ( https://nmap.org ) at 2021-09-19 13:49 CEST
NSE: Updating rule database.
NSE: Script Database updated successfully.
Nmap done: 0 IP addresses (0 hosts up) scanned in 0.28 seconds
```

all scripts are located at  `/usr/share/nmap/scripts/`

```shell-session
find / -type f -name ftp* 2>/dev/null | grep scripts
```
