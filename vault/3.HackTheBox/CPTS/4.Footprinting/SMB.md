`Server Message Block` (`SMB`) is a client-server protocol that regulates access to files and entire directories and other network resources such as printers, routers, or interfaces released for the network. [SMB](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-smb/f210069c-7086-4dc2-885e-861d837df688) first became available to a broader public, for example, as part of the OS/2 network operating system LAN Manager and LAN Server.

The SMB protocol enables the client to communicate with other participants in the same network to access files or services shared with it on the network.It mostly used in window but can be user in Linux and work on server client Architecture.

`Access Control Lists` (`ACL`)  are managed using something called `ccess Control Lists` (`ACL`)., which control. They can be controlled in a fine-grained manner based on attributes such as `execute`, `read`, and `full access` for individual users or user groups.

## Samba

Alternative of SMB server is Samba, which is developed for Unix-based operating systems. Samba implements the Common Internet File System (`CIFS`) network protocol. This allows Samba to communicate effectively with newer Windows systems. Therefore, it is often referred to as SMB/CIFS.

- SMB/CIFS (older versions) can used
    - TCP 137, 138, 139 (mainly with NetBIOS, an older Windows networking system)

- Modern SMB versions (SMB 2, SMB 3) used
    - TCP 445 only (more direct and efficient)

|**SMB Version**|**Supported**|**Features**|
|---|---|---|
|CIFS|Windows NT 4.0|Communication via NetBIOS interface|
|SMB 1.0|Windows 2000|Direct connection via TCP|
|SMB 2.0|Windows Vista, Windows Server 2008|Performance upgrades, improved message signing, caching feature|
|SMB 2.1|Windows 7, Windows Server 2008 R2|Locking mechanisms|
|SMB 3.0|Windows 8, Windows Server 2012|Multichannel connections, end-to-end encryption, remote storage access|
|SMB 3.0.2|Windows 8.1, Windows Server 2012 R2||
|SMB 3.1.1|Windows 10, Windows Server 2016|Integrity checking, AES-128 encryption|

#### **NetBIOS:**

NetBIOS stands for Network Basic Input/Output System. It's a legacy networking service that was originally designed to allow computers on the same local network to communicate with each other.It was created in the 1980s and was commonly used in Windows networks, especially before the Internet Protocol (IP) became standard for everything.

- Sharing files and printers
- Naming and identifying computers on the network
- Sending simple messages

**SAMBA-3** Gained the ability to join an Active Directory (AD) domain as a member.That means a Linux server running Samba 3 can act like a Windows machine that's part of a centralized login and file sharing system.

**SAMBA-4** took a big step forward: it can now act as an Active Directory Domain Controller (AD DC).That means Samba 4 can replace a Windows Server Domain Controller, managing:

    User logins
    - Permissions
    - Group policies
    - Directory services

## ⚙️ Background Programs (Daemons) in Samba

Samba is powered by small background services, known as **daemons** in Unix/Linux systems.

| Daemon                       | Purpose                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| **`smbd`**                   | Handles **file sharing, printer sharing**, and **user authentication** (the main SMB server). |
| **`nmbd`**                   | Handles **NetBIOS name resolution** and **browsing services** (like workgroup visibility).    |
| **`winbindd`** _(optional)_  | Manages **user and group information from Windows domains**.                                  |
| **`samba`** (in Samba 4)     | Full **Active Directory Domain Controller** daemon (replaces `smbd`/`nmbd` in AD role).       |

## Workgroups and SMB Networks

- A workgroup is a group of computers that share resources without a central server.
- Each host (computer) is part of a workgroup (e.g., `WORKGROUP` by default).
- In workgroup mode, computers find each other using NetBIOS broadcasts not centralized servers.
- You can have multiple workgroups in the same local network.

- Each host needs a unique NetBIOS name on the network.There are two main ways name registration is done:
     Peer-to-peer: Each host broadcasts its name (less efficient, common in small networks).Centralized: A NetBIOS Name Server (NBNS) like WINS is used.

```shell-session
   usershare allow guests = yes
<snip>
```

| **Setting**                    | **Description**                                                       |
| ------------------------------ | --------------------------------------------------------------------- |
| `[sharename]`                  | The name of the network share.                                        |
| `workgroup = WORKGROUP/DOMAIN` | Workgroup that will appear when clients query.                        |
| `path = /path/here/`           | The directory to which user is to be given access.                    |
| `server string = STRING`       | The string that will show up when a connection is initiated.          |
| `unix password sync = yes`     | Synchronize the UNIX password with the SMB password?                  |
| `usershare allow guests = yes` | Allow non-authenticated users to access defined share?                |
| `map to guest = bad user`      | What to do when a user login request doesn't match a valid UNIX user? |
| `browseable = yes`             | Should this share be shown in the list of available shares?           |
| `guest ok = yes`               | Allow connecting to the service without using a password?             |
| `read only = yes`              | Allow users to read files only?                                       |
| `create mask = 0700`           | What permissions need to be set for newly created files?              |

## Dangerous Settings

Some of the above settings already bring some sensitive options. However, suppose we question the settings listed below and ask ourselves what the employees could gain from them, as well as attackers.

| **Setting**                 | **Description**                                                     |
| --------------------------- | ------------------------------------------------------------------- |

| `read only = no`            | Forbid the creation and modification of files?                      |
| `writable = yes`            | Allow users to create and modify files?                             |
| `guest ok = yes`            | Allow connecting to the service without using a password?           |
| `enable privileges = yes`   | Honor privileges assigned to specific SID?                          |
| `create mask = 0777`        | What permissions must be assigned to the newly created files?       |
| `directory mask = 0777`     | What permissions must be assigned to the newly created directories? |
| `logon script = script.sh`  | What script needs to be executed on the user's login?               |
| `magic script = script.sh`  | Which script should be executed when the script gets closed?        |
| `magic output = script.out` | Where the output of the magic script needs to be stored?            |
