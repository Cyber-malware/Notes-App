Account lockout policies are used to prevent brute force attacks by locking users out after a set number of failed login attempts. However, if poorly implemented, they can be abused to cause **denial of service (DoS)** for legitimate users.
- **Too lax:** Allows brute force attempts.
- **Too strict:** Enables attackers to lock out accounts repeatedly.
- Even with short unlock periods (e.g., 5 minutes), attackers can automate repeated failed attempts to keep users locked out indefinitely.
In a pentest, an account locked after 6 failed attempts and auto-unlocked after 5 minutes. A script was used to send 6 invalid logins every 5 minutes, effectively locking the user out indefinitely.

#### **OCR Engine Bypass:**
A CAPTCHA was present on the sign-up page. Upon inspection, it was discovered that the text was easily readable through OCR engines. Initially, this behavior was verified using Google’s Tesseract OCR Engine. CAPTCHAs were generated by refreshing the page multiple times and were successfully converted to text using the same method.
![[Screenshot_2025-08-11_03-24-10.png]]

Next, by using the wrapper for Google’s Tesseract OCR Engine, the png image containing the CAPTCHA value was converted into text. The following command was used.
```bash
tesseract -l eng captcha.png captcha;echo; echo "Captcha value is"; cat captcha.txt
```

Each time a new CAPTCHA was generated, it had to be downloaded, processed through Google’s Tesseract OCR Engine, and entered into the HTTP request before sending. To automate and scale this process, a Python script leveraging Selenium was developed. This script enabled users to automatically extract CAPTCHA values and inject them into the original requests, effectively bypassing the CAPTCHA security mechanism.

Use Captcha_Bypass_static_1.py script in same directory.

#### **DYNAMIC CAPTCHA GENERATION BYPASS USING OCR**
During another assessment, a similar CAPTCHA was encountered. Using Google’s Tesseract OCR Engine, it was possible to convert the image into text. However, there was a challenge: the CAPTCHA image could not be directly downloaded because the application dynamically generated a new image with each request. In essence, the website employed dynamic CAPTCHA generation, continuously creating fresh images to hinder traditional downloading methods.
![[Screenshot_2025-08-11_03-29-02.png]]

To address this challenge, a solution was devised using Selenium. The process involved taking a full-page screenshot and precisely cropping the CAPTCHA from the screenshot image and subsequently processing the image through OCR.

- The process began with capturing screenshots and cropping the CAPTCHA. Using Selenium WebDriver, the Python script opened the registration page, captured a full-page screenshot, and precisely selected the region containing the CAPTCHA for cropping. This cropped CAPTCHA image was then saved separately. 
- Next, the cropped image was processed using the Tesseract OCR library (Pytesseract) to extract the text. The extracted CAPTCHA value was automatically entered into the corresponding form field on the web page, after which the script submitted the form. This approach effectively bypassed the CAPTCHA protection and enabled user registration without human intervention.

Use Captcha_Bypass_dynamic_2.py script in same directory.
